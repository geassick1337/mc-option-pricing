# Как количество симуляций Монте-Карло влияет на точность оценки стоимости опциона

**Исследовательский проект по финансовой математике (quantitative finance).**
Математическое исследование на основе геометрического броуновского движения.

> ⚠️ Проект учебный. Он изучает математические свойства метода в заданной модели рынка и **не предназначен для реальных инвестиционных решений**.

---

## 1. Исследовательский вопрос

> **Как количество случайных экспериментов (симуляций) *N* влияет на точность оценки стоимости европейского колл-опциона, полученной методом Монте-Карло?**

Подвопросы:
1. По какому закону убывает ошибка при росте *N*?
2. Когда увеличение *N* заметно улучшает оценку, а когда прирост точности становится «слишком дорогим»?
3. Одинакова ли скорость сходимости для разных опционов?
4. Можно ли получить ту же точность с меньшим числом симуляций?

## 2. Гипотезы

| № | Гипотеза |
|---|---|
| **H1** | Ошибка оценки убывает пропорционально **1/√N**: в логарифмических осях это прямая с наклоном ≈ −0,5. |
| **H2** | Разброс оценок вокруг истинного значения подчиняется нормальному закону, поэтому 95%-й доверительный интервал `оценка ± 1,96·SE` накрывает истину примерно в 95% случаев (при достаточно большом N). |
| **H3** | Наклон −0,5 одинаков для любых опционов, но **уровень** ошибки зависит от параметров (страйк, волатильность). |
| **H4** | Метод антитетических переменных снижает ошибку при том же N. |

## 3. Теоретическая основа

*(Простое объяснение каждого понятия: [`docs/THEORY_SIMPLE.md`](docs/THEORY_SIMPLE.md).)*

**Модель рынка (риск-нейтральная мера).** Цена акции подчиняется геометрическому броуновскому движению:

```
dS = r·S dt + σ·S dW
```

Точное решение для момента *T*:

```
S_T = S0 · exp( (r − σ²/2)·T + σ·√T·Z ),     Z ~ N(0, 1)
```

**Цена европейского колл-опциона** — дисконтированное среднее выплаты:

```
C = e^(−rT) · E[ max(S_T − K, 0) ]
```

**Эталон — формула Блэка — Шоулза** (точное решение той же модели):

```
C = S0·Φ(d1) − K·e^(−rT)·Φ(d2),
d1 = [ln(S0/K) + (r + σ²/2)T] / (σ√T),   d2 = d1 − σ√T
```

**Метод Монте-Карло.** Генерируем *N* независимых значений `Z_i`, считаем выплаты `X_i = e^(−rT)·max(S_T^(i) − K, 0)` и берём среднее:

```
Ĉ_N = (1/N) · Σ X_i
```

**Почему 1/√N.** По закону больших чисел `Ĉ_N → C`. По центральной предельной теореме ошибка приближённо нормальна со стандартным отклонением

```
SE = σ_X / √N,     σ_X = √Var(X)
```

В нашей модели `σ_X` можно вычислить точно (см. `discounted_payoff_std` в коде): **σ_X ≈ 14,72**. Значит, теоретическая ошибка — `14,72/√N`.

**Практический вывод из формулы:** чтобы уменьшить ошибку в 10 раз, нужно в **100** раз больше симуляций.

## 4. Методика эксперимента

**Параметры базового опциона:** S0 = 100, K = 100, T = 1 год, r = 5%, σ = 20%.
**Эталон (Блэк — Шоулз): C = 10,4506.**

Для каждого N ∈ {10, 30, 100, 300, 1 000, 3 000, 10 000, 30 000, 100 000, 300 000}:
1. делаем **300 независимых повторов** оценки Монте-Карло;
2. считаем смещение, RMSE, среднюю и максимальную ошибку;
3. проверяем, как часто 95%-й доверительный интервал накрывает эталон;
4. замеряем время вычисления.

Затем отдельно: антитетические переменные (H4) и пять разных опционов (H3).
Генератор случайных чисел зафиксирован (`seed = 2026`), поэтому **все результаты воспроизводимы**.

### 5.5. Надёжность доверительных интервалов (H2)

![Накрытие CI](figures/06_ci_coverage.png)

При N ≥ 100 доля накрытия колеблется около 95% (93–97%, с учётом шума при 300 повторах). При **N = 10 накрытие всего ≈ 85%**: выборка слишком мала, распределение оценки сильно скошено (выплата опциона — несимметричная величина), и нормальное приближение не работает.

### 5.6. Цена точности: время

![Время](figures/07_time_vs_error.png)

Время растёт примерно линейно с N (300 000 симуляций ≈ 6 мс), а ошибка — только как 1/√N. Поэтому каждое следующее «улучшение» обходится всё дороже.

**Сколько симуляций нужно?** Из формулы `N = (1,96·σ_X / δ)²` для полуширины 95%-го интервала δ:

| Нужная точность δ (±) | Требуемое N |
|---:|---:|
| 1,0 | ≈ 833 |
| 0,1 | ≈ 83 000 |
| 0,01 | ≈ 8,3 млн |
| 0,001 | ≈ 832 млн |

Каждая лишняя «цифра после запятой» требует в 100 раз больше симуляций.

| N | RMSE обычный | RMSE антитетический | Снижение дисперсии |
|---:|---:|---:|---:|
| 100 | 1,479 | 0,986 | ×2,25 |

В среднем дисперсия падает примерно **в 2,2 раза**, то есть та же точность достигается примерно с вдвое меньшим числом симуляций. Работает потому, что выплата колл-опциона монотонна по Z, и пары `(Z, −Z)` отрицательно коррелируют.

## 6. Выводы

| Гипотеза | Итог | Обоснование |
|---|---|---|
| **H1** (ошибка ~ 1/√N) | ✅ подтвердилась | наклон −0,502; RMSE·√N ≈ const ≈ 14,7; опыт совпадает с теорией `14,72/√N` |
| **H2** (CI накрывает ~95%) | ✅ частично | при N ≥ 100 накрытие ≈ 93–97%; при N = 10 ≈ 85% (мало данных, скошенное распределение) |
| **H3** (наклон тот же, уровень разный) | ✅ подтвердилась | наклон одинаков; относительная ошибка у опциона вне денег в ~3 раза выше, чем у опциона у денег |
| **H4** (антитетика помогает) | ✅ подтвердилась | дисперсия ниже примерно в 2,2 раза |

**Почему так получилось.** Монте-Карло — это среднее независимых случайных величин. Его ошибка по ЦПТ равна σ_X/√N, поэтому любое увеличение точности «покупается» квадратично растущим числом симуляций.

**Когда увеличение N выгодно, а когда нет.** От 10 до 1 000 симуляций ошибка падает с ≈ 4,8 до ≈ 0,44 — резкий выигрыш. От 100 000 до 300 000 (в 3 раза больше работы) ошибка падает лишь с 0,048 до 0,025 в абсолютных числах — выигрыш в 0,02 денежной единицы. Для оценки опциона ценой ≈ 10 этого может уже хватать.

## 7. Практическая ценность

- Показано на конкретных числах, как компьютерная симуляция оценивает стоимость инструмента, когда нужно учитывать множество возможных сценариев.
- Зависимость точности от вычислительных затрат измерена, а не просто заявлена.
- Определено, когда увеличение числа симуляций существенно улучшает оценку, а когда прирост точности становится небольшим (закон убывающей отдачи 1/√N).
- Получена готовая модель для изучения вероятностей, статистики (ЦПТ, доверительные интервалы, RMSE) и принципов финансовой математики.
- Метод переносится на опционы, для которых точной формулы нет (азиатские, барьерные, с несколькими активами), где Монте-Карло часто единственный практичный вариант.

## 8. Ограничения

- Модель Блэка — Шоулза предполагает постоянные σ и r, логнормальные цены и отсутствие скачков. Реальные рынки сложнее.
- Рассмотрен только европейский опцион, для которого есть точный эталон и точная схема симуляции (без ошибки дискретизации по времени).
- RMSE оценивается по 300 повторам, то есть имеет собственную погрешность около ±4%.
- Время вычислений зависит от компьютера; важна форма зависимости, а не конкретные миллисекунды.
- Используются псевдослучайные числа NumPy; квази-Монте-Карло (последовательности Соболя) могло бы сходиться быстрее 1/√N, но выходит за рамки проекта.

## 9. Возможные продолжения

- Квази-Монте-Карло (последовательности Соболя) и сравнение скорости сходимости.
- Контрольные переменные как ещё один способ снижения дисперсии.
- Азиатский или барьерный опцион (где нет простой формулы).
- Схема Эйлера по шагам времени: ошибка дискретизации против статистической ошибки.

## 10. Как запустить

```bash
git clone https://github.com/<ваш-логин>/mc-option-pricing.git
cd mc-option-pricing
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python tests/test_pricing.py        # проверка корректности (8 тестов)
python run_experiments.py           # полный запуск (графики -> figures/, таблицы -> results/)
python run_experiments.py --quick   # быстрая проверка
```

Минимальный пример использования:

```python
import numpy as np
from mcoptions import Params, black_scholes_call, mc_call

p = Params(S0=100, K=100, T=1, r=0.05, sigma=0.2)
rng = np.random.default_rng(0)
estimate, std_error = mc_call(p, n=100_000, rng=rng)
print(estimate, "±", 1.96 * std_error, "| точно:", black_scholes_call(p))
```
